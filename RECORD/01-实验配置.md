# 实验一 实验配置

本表对应报告第二部分实验设置，字段来源为各次运行的 `config.json`。

## 一 通用配置

五种方法共用，若某方法偏离须在第五节说明原因。

| 项目 | 取值 |
| --- | --- |
| 基座模型 | Qwen/Qwen3-0.6B |
| 精度 | 训练侧权重以 float32 载入，前向与反向经 autocast 降至 float16，评测侧权重即取 float16 |
| 最大序列长度 | 512 |
| Epoch | 按方法分设，全参微调 3、LoRA 3、P-Tuning v2 3，P2.5 定稿 |
| Batch Size | 按方法分设，全参微调 4、LoRA 8、P-Tuning v2 4 |
| 梯度累积步数 | 依次 16、8、16，有效批一律 64 |
| Learning Rate | 按方法分设，全参微调 2.5e-5、LoRA 1.0e-4、P-Tuning v2 1.2e-2，P2.5 定稿 |
| 学习率调度 | 余弦退火，线性预热，预热比例 0.03 |
| 优化器 | AdamW，权重衰减 0，梯度范数上限 1.0 |
| 随机种子 | 42 |
| 梯度检查点 | 全参微调与 LoRA 开启，P-Tuning v2 关闭 |
| GPU 型号 | R0 至 R2-12 为 Tesla V100-SXM2-16GB，可用显存 15.77 GiB；P2.6 起为 NVIDIA A10，显存 24 GiB，2026-10-17 换机 |
| 单次训练时长 | 待 P2.6 正式训练回填 |
| 显存峰值 | 待 P2.6 正式训练回填 |

精度一行记两层。训练侧权重以 float32 载入，前向与反向经 autocast 在算子内降至 float16，故权重本体与优化器状态留在 float32 上。若权重按计算精度载入，梯度随之同为 float16，而梯度缩放的反缩放要求在 float32 上进行，torch 遇 float16 梯度即报错，见 `LOG/02-问题与解决.md` Q12。评测侧不开梯度缩放，权重直接取计算精度 float16，五种方法同此，故横向比较不受影响。换机后精度不随硬件自动切换。A10 算力 8.6，按算力自动判定会取 bfloat16，为使 P2.6 与 M0 及 P2.5 的全部读数处于同一数值路径，训练与评测两侧均显式指定 float16。

微批与梯度检查点两项按方法分设，乘积之积一律为 64，故每轮步数与优化轨迹不因该分设而变，偏离的成因为显存，见第五节。

## 三 超参选择依据

记录学习率与轮数是如何确定的，须说明依据的数据来源，仅可为 GSM8K 训练集内部划出的开发集。选定取值一列据本节末的搜索结果回填，三种方法的取值均由第三轮的运行定稿，全参微调与 LoRA 据 R2-9，P-Tuning v2 据 R2-12。

| 方法 | 搜索范围 | 选定取值 | 依据数据集 | 选择准则 |
| --- | --- | --- | --- | --- |
| Full SFT | 学习率 2.5e-5、5.0e-5、1.0e-4、2.0e-4，轮数 1 至 5 | 学习率 2.5e-5，轮数 3 | dev | 开发集准确率最高，差值不足一个标准误时取较小学习率与较早轮数 |
| LoRA | 学习率 1.0e-4、2.0e-4、4.0e-4，轮数 1 至 5 | 学习率 1.0e-4，轮数 3 | dev | 同上 |
| P-Tuning v2 | 学习率首轮 1.5e-4、3.0e-4、6.0e-4 判为未收敛而弃用，重扫取 3.0e-3、6.0e-3、1.2e-2，轮数 1 至 5，前缀初始化取置零与随机两点 | 学习率 1.2e-2，前缀初始化随机，轮数 3 | dev | 同上 |

学习率档位取各方法初值及其半值与二倍值，初值为按可训练参数量与更新方式取的经验值，全参微调最低、P-Tuning v2 最高。轮数不单独占一次运行，由选定学习率下每轮末的开发集读数序列给出，故运行轮数上限取 5，够看到读数由升转降的拐点。P-Tuning v2 另扫前缀初始化两点，成因为该取值只改前缀起点的位置而不改可训练参数量，故不牵动横向比较的口径，理由与实测见 `LOG/02-问题与解决.md` Q15。

读数的取法按档分设。学习率档与前缀初始化档取 `eval.mode` 为 final，只在末次迭代末评一次，轮数档保持 every_epoch，每轮末评一次。依据是一次开发集全量评测的耗时与一轮训练同量级，R2-4 实测 16 条用 38 秒，按评测批 16 外推 400 条约 10 至 16 分，而学习率档只需末轮读数，故不必付每轮一次的代价。轮数一维的曲线由每方法一次的五轮运行给出，该次运行同时贡献学习率与轮数的联合读数。

开发集为 400 条，在准确率 0.6 附近的二项标准误约 0.0245，小于此数的两档差异不判为有别。该准则先于搜索结果定下，以免据读数反向解释。

置零臂的轮数曲线未出现下降拐点，五轮增量依次为 22、12、6 与 7 条样本，自第 3 轮起已落在一个标准误所对应的约 9 条之内，即该臂自第 3 轮起在噪声水平上持平。但该曲线测于置零臂，而 M3 的最终配置取随机初始化，两臂的收敛速度不同，把该曲线搬给随机一臂不成立，故轮数一维另由 R2-12 的一次五轮运行给出，取随机初始化与同一学习率。

三处须一并记。其一，学习率按 cosine 调度到计划总步数上归零，故轮数一维与调度耦合，某一轮数下的读数不是另一轮数下模型的延长，同一轮数内的跨方法比较不受影响；R2-12 的第 3 轮读数与 R2-10 随机一臂 3 轮的 0.4175 之间正因此而生差异，其量级后由 R2-9 的两处对照测出，低于一个标准误，见下段。其二，随机初始化随装配波动，本机六次实测的首步损失落在 4.7491 至 11.7336，容器内 R2-10 随机一臂第 10 步为 5.1815，故该臂读数条件于种子 42 的一次抽样，M3 的最终读数受此影响，报告须说明。其三，R2-10 两档的显存峰值均为 10.39 GiB。

LoRA 的曲线在该轮数范围内测不出差别。五个读数为 195、193、196、202 与 201 条，全距 9 条，小于一个标准误所对应的约 10 条，训练损失在 0.58 附近走平而远高于全参微调同期，说明尚未过拟合。按准则的字面应用，五轮两两不可分而应取最早一轮，即 1 轮。此处取 3 轮，理由有二。其一，第 3 轮这一点在本任务之外已有独立复现，R2-6 的 LoRA 同学习率同取三轮 333 步得 197 条，与本臂第 3 轮的 196 条相差 1 条；而 1 轮这一点在本次扫描里最不可外推，111 步的计划把余弦压缩到预热之后仅剩 95 步，与正式运行的调度偏离最大。其二，全参微调已定为 3 轮，取 3 轮可使两法同轮数，若 R2-12 亦落在 3 轮，则三方法在最终配置上的差别只剩适配机制一项。故 LoRA 的轮数定为 3。

两处跨任务的对照给出本节的一项方法学事实。R2-8 的全参微调三轮 333 步为 210 条，本臂第 3 轮为 205 条，相差 5 条；R2-6 的 LoRA 三轮 333 步为 197 条，本臂第 3 轮为 196 条，相差 1 条。即同一学习率下把计划总步数由 333 改为 555 而在同一步数处比较，两法的读数变动均低于一个标准误，故调度耦合在 3 轮处的实际代价可忽略。该事实使上一段为 R2-12 记下的警示收窄为可估，R2-12 第 3 轮的读数可与 R2-10 随机一臂 3 轮的 167 条对看，两者相差超过约 10 条方须另找成因，不可径归为调度不同。

负结果未变。R2-9 的十个读数无一超过 M0 的 0.6350，其中最高者为全参微调第 3 轮的 205 条。截至 R2-12，全部微调读数共 34 个、训练档共 18 个，最高值仍为 R2-8 全参微调 2.5e-5 的 210 条即 0.5250，与本臂第 3 轮相差 5 条，两者不可分。横向比较另得一项，全参微调最优 205 条与 LoRA 最优 202 条相差 3 条，两法在目标领域上测不出差别；而 P-Tuning v2 现有的最高读数 171 条低 34 条，已逾 3 个标准误，故该方法在目标领域上仍明确落后于另两法，其前缀初始化一改虽已不落在另两法的区间之外，仍未追平。

R2-12 为第三轮的最后一次任务，2026-10-16 走通，一次 P-Tuning v2 随机前缀的五轮 every_epoch 运行，学习率与前缀初始化与 R2-10 的随机一臂相同，故本次曲线与该臂只差前缀起点一处。五轮读数如下。

## 五 偏差说明

记录相对第一节通用配置的偏离，以及本实验中未受控的变量。

答案抽取规则由 v1 递增至 v2，第四节相应字段的取值随之更新。变更理由如下。R1-1 任务在 v1 下运行，ARC 上有 39 条降级与 45 条失败。逐条核对发现模型多以标签点号接选项正文作答，例如 `A. 32° F B. 41° F C. 78° F D. 98° F`，v1 的第二级取全文末位孤立字符，在此类输出上取到正文末字母 `F` 与 `s`，既不在本题标签集合内，又因取到值而中止级联，使本可由正文比对接住的样本记成降级或失败。v2 的三处改动为，第一级引导语窗口只认本题标签集合内的字符，窗口内取不到则回溯至更早的引导语命中，全无则下沉而非返回；第二级末位字符同样只认本题标签，集合外则下沉；新增第四级前置标签，识别输出开头的 `B.` 一类形态，标号之后须紧跟空白，以免把 `3.5 m/s` 读作标签 3。集合外的字符不再就地返回，而是记下备作降级，待四级走完仍无命中时才取出，故三选项题被答成 D 一类情形仍记为降级而非失败。

改动后据已落盘的逐条明细在本机离线重算，未重跑模型，未新增 DLC 任务。ARC 准确率由 0.4923 升至 0.5205，判对增 33 条、减 0 条，原先判对的 577 条取值一条未变，抽取失败由 45 条降至 0 条，降级由 39 条降至 1 条。GSM8K 侧不受影响，读数仍为 0.6035。重算由 `exp1/scripts/reextract.py` 完成，逐条比对取值，原先判对的样本若出现取值改动即判 FAIL 并中止。

答案抽取规则由 v2 递增至 v3。P2.6 的 M2 与 M3 在 ARC 上分别有 279 条与 346 条抽取失败，逐条核对见 `LOG/02-问题与解决.md` Q20，其中两类输出带完整作答内容而原级联不覆盖。一类为标签后只有空白再接正文，如 `B The engineers tested different building designs ...`，v2 的第四级要求标签后有标号，故不命中；另一类为选项正文之前多出描述性成分，v2 的第三级只比对输出开头八十字符，故不命中。v3 在原有四级之后追加两级，前四级判定不变。第五级为无标点标签，用于第一类，标签后须接空白再接大写词，故 `A car is moving` 一类冠词句仍不命中。第六级为全文正文查找，用于第二类，检测门槛四字符，接受门槛五字符，只接受唯一命中，命中两处以上视为歧义放弃。第五与第六级同时命中而标签不一致时判失败并单记 conflict，不在冲突处猜测。

v3 的读数由离线重算取得，重跑生成一面未动，所用脚本为 `exp1/scripts/offline_reextract_arc.py`，输入为已落盘的逐条预测与原始 ARC 题目文件，输出为同目录的 `_v3` 文件，原始预测保留。四份文件逐条比对后无一条原先判对的样本改动取值。ARC 准确率 M0 0.5205 不变，M1 自 0.5290 升至 0.5444，M2 自 0.4642 升至 0.5734，M3 自 0.3805 升至 0.4991，抽取失败率自 0、0.0973、0.2381、0.2952 降至 0、0.0768、0.0333、0.0904。

两套口径的结论方向不同，须在报告中显式说明。v2 下 ARC 的次序为 M1 0.5290、M0 0.5205、M2 0.4642、M3 0.3805，M2 与 M3 均低于基线，可读作遗忘；v3 下次序为 M2 0.5734、M1 0.5444、M0 0.5205、M3 0.4991，M2 与 M1 高于基线，M3 低 25 条即约 1.1 个标准误。v2 的失败样本中有大量实为完整作答而被判失败者，故主口径取 v3，v2 读数作为抽取规则敏感性的证据单列。这一对照本身说明，在这类格式漂移严重的输出上，抽取规则的选择足以改变遗忘是否出现的判断。

M2 在 v3 下的 ARC 读数高于基线 62 条即约 5.3 个百分点，已在两个标准误之上，而同一方法的 GSM8K 读数低于基线 209 条，两列方向相反。该反差不得径读作 LoRA 提升了科学推理。可分离的成分至少有二，其一为输出形态改变使更多作答可由全文正文查找级读出，而该级在复述型输出上比标签型宽松，其二为方法本身的迁移效果。报告须把该读数与截断率 0.2696、生成均长一并解读，并以 P4.2 的同批配对检验确认差值的稳定性，不得据单一准确率下结论。

微批大小按方法分设，相对第一节通用配置记单一 Batch Size 的写法构成偏离，其成因为显存而非优化。显存峰值由三项构成，全参微调恒占的 float32 参数、梯度与优化器状态合计 8.88 GiB，正比于微批乘序列乘词表的 logits 及其两份 float32 副本，以及不开梯度检查点时正比于微批的激活值。经 R2-1 实测，全参微调在微批 8 下已分配 12.82 GiB，两个适配器方法在微批 16 下达 14.75 GiB，均超出单卡 15.77 GiB 的可用上限；经 R2-2 实测，全参微调在微批 4 下走通且峰值 12.70 GiB，两个适配器方法在微批 8 且不开梯度检查点下仍不足，两者均在已分配 13 GiB 以上时申请 2.09 GiB 失败，成因为激活值约 10 GiB 主导。最终取值为全参微调微批 4、LoRA 微批 8、P-Tuning v2 微批 4，梯度累积步数依次为 16、8、16，有效批一律为 64，每轮步数与优化轨迹不因该偏离而变，详见 `LOG/02-问题与解决.md` Q13 与 Q14。该组取值经 R2-4 实测确认，LoRA 在微批 8 与梯度检查点同开下显存峰值 10.26 GiB，P-Tuning v2 在微批 4 与不开检查点下 10.12 GiB，均在 15.77 GiB 的可用上限之内。

梯度检查点一项同样按方法分设，全参微调与 LoRA 开启，P-Tuning v2 关闭。前两者的显存由激活值主导，开启后激活值在反向时重算而不留存；后者开启会使框架在逐层调用前丢弃前缀所依附的注意力缓存，前向的掩码长度与键长随之不符，见 Q14。关闭检查点的代价是激活值随微批线性增长，故其微批与全参微调同取 4。训练中的中间评测批取 16，与独立评测的 GSM8K 批 32 不同，但贪心解码的输出与批大小无关，故中间评测与独立评测的读数仍可比。

未受控变量一项，ARC 的抽取失败率与降级率下降是规则改进的结果，不由模型行为变化引起，故 M0 至 M4 的横向比较不受影响，但 ARC 的读数不可与本记录更新之前的外部数值直接比较。
