# 实验一 计划总览

## 一 实验目标

以数学推理为目标领域，使用 GSM8K 训练集对基座模型进行领域适配，比较不同适配方法在目标领域上的能力提升，并通过 ARC-Challenge 观察适配之后原有通用能力的保持情况，进而分析灾难性遗忘现象及其缓解方式。

## 二 基座模型与数据集

| 项目 | 内容 | 用途 |
| --- | --- | --- |
| 基座模型 | Qwen/Qwen3-0.6B | 全部方法的共同起点 |
| 领域训练集 | openai/gsm8k，配置 main，train 7473 条 | 仅用于训练 |
| 领域测试集 | openai/gsm8k，配置 main，test 1319 条 | 仅用于评测 |
| 通用能力测试集 | allenai/ai2_arc，配置 ARC-Challenge，test | 仅用于评测，不参与训练 |

## 三 方法清单

| 编号 | 方法 | 说明 | 状态 |
| --- | --- | --- | --- |
| M0 | Base Model | 不训练，直接评测，作为全部对比的基准 | 已完成，测试集读数为 GSM8K 0.6035 与 ARC-Challenge 0.5205，运行标识 R1-1；同一开发集上的对照读数于 2026-10-15 取得，为 0.6350，见 `RECORD/01-实验配置.md` 第三节 |

| M2 | LoRA | 低秩适配，需记录 rank、alpha、学习率、epoch | 实现完成，学习率取 1.0e-4、轮数取 3，2026-10-15 定稿 |
| M3 | P-Tuning v2 | 冻结主干参数，训练可学习 prefix，需记录 prefix length、学习率、epoch | 实现完成，首轮三档未收敛，2026-10-15 重扫三档后学习率定为 1.2e-2，前缀初始化比较置零与随机两臂后定为随机，轮数取 3，2026-10-16 定稿 |
| M4 | 自研方法 | 在 LoRA 基础上调整 rank 或轮数，或引入额外约束以缓解遗忘 | 未开始，方案待 P3.1 定案 |

## 四 硬性约束

- 四种训练方法使用完全相同的 GSM8K 训练集与测试集划分，严禁测试集泄漏。
- 评测统一使用同一套 prompt 与答案抽取方式。
- 统一设置 enable_thinking 为 False，若调整必须在报告中说明。
- ARC-Challenge 只用于评测，任何方法都不得将其用于训练或超参选择。
- 报告须记录 GPU 型号、learning rate、batch size、epoch、最大序列长度与训练时间。

## 六 运行方式

本机完成代码开发与调试，代码经 GitHub 仓库同步至阿里云 PAI 平台，在 DLC 上创建训练任务执行。数据集与模型权重不进入代码仓库。单卡即可满足本实验的算力需求，公共资源配额上限为 GPU 2 卡与 CPU 8 核，不引入多卡方案。计算资源前段为单卡 V100，2026-10-17 起为单卡 A10，精度一律取 float16，换机边界与理由见 `RECORD/02-环境信息.md` 第二节。

详细链路见 `PLAN/03-代码结构.md`。
