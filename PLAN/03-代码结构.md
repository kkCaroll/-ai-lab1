# 实验一 代码结构

本节为提案，待确认后据此建立仓库目录。

## 一 目录布局

仓库根目录即当前实验文件夹，代码置于 `exp1/` 之下，与 `PLAN/`、`RECORD/`、`LOG/`、`DLC使用文档/` 平级。

```
exp1/
  configs/              各方法的训练配置
    base.yaml
    full_sft.yaml
    lora.yaml
    ptuning.yaml
    custom.yaml
  src/
    data.py             数据加载与 prompt 构造
    extract.py          答案抽取
    train.py            统一训练入口
    eval.py             统一评测入口
    methods/
      sft.py
      lora.py
      ptuning.py
      custom.py
    utils.py            日志、随机种子、显存统计
  scripts/
    smoke_infer.py      P0.2 最小推理验证
    run_eval.sh         按方法批量评测
    export_tables.py    由记录导出报告用表格
  tests/
    test_extract.py
  requirements.txt
```

数据集与模型权重不进入仓库，通过 OSS 挂载或本机路径提供。

## 二 脚本接口

统一入口，方法差异全部由参数控制，不为每种方法单独修改文件内容。

训练入口

```
python -m src.train --method {sft|lora|ptuning|custom} \
                    --config configs/<method>.yaml \
                    --data_dir <挂载路径> \
                    --output_dir <输出路径> \
                    --seed 42
```

评测入口

```
python -m src.eval --model_path <路径> \
                   --adapter <路径或留空> \
                   --dataset {gsm8k|arc} \
                   --split {test} \
                   --output <结果文件>
```

被评测的方法与训练超参通过配置文件传递，训练与评测共用 `src/data.py` 中的 prompt 模板，以保证 R8 得到控制。

## 三 输出约定

每次运行在输出目录下生成一份运行记录，供 `RECORD/01-实验配置.md` 直接誊录。

| 文件 | 内容 |
| --- | --- |
| `config.json` | 本次运行的全部超参快照 |
| `env.json` | 库版本、GPU 型号、显存峰值 |
| `metrics.json` | 训练损失曲线与评测准确率 |
| `predictions.jsonl` | 逐条预测与抽取结果，供人工抽查 |
| `train.log` | 训练日志 |

输出目录以运行标识命名，不复用旧目录，以规避 OSS 不支持覆盖写的问题。
